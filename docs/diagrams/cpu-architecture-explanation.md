# CPU 架构图说明

本文档用于解释 `cpu-soc-overview.png` 和 `cpu-core-microarchitecture.png` 中的模块、接口与反馈路径。图片本身仅保留必要的英文标注，不包含图内标题；插入设计报告时，由报告正文统一生成图题和编号。

## 1. SoC 层次与接口

SoC 总览图以 `student_top` 为系统边界，主要包含 CPU 核、两路指令存储器和外设桥三个部分。

CPU 核实例 `Core_cpu` 对外提供两组 32 位只读取指接口。第一路访问当前 PC 对应的指令，第二路访问 `PC+4` 对应的相邻指令；`student_top` 使用地址的 `[13:2]` 位访问两路 IROM。两路取指数据共同进入 CPU 前端，用于形成最多包含两条连续指令的发射包。

CPU 通过一组统一的数据访问接口连接 `perip_bridge`。该接口包含 32 位地址、32 位写数据、32 位读数据、写使能和两位访问宽度掩码。桥接模块根据地址选择 BRAM 或 MMIO 目标：

| 目标 | 地址范围或地址 | 作用 |
|---|---|---|
| BRAM | `0x8010_0000`--`0x8013_FFFF` | 数据存储器，支持 byte、half 和 word 访问 |
| SW0 | `0x8020_0000` | 读取低 32 位虚拟开关 |
| SW1 | `0x8020_0004` | 读取高 32 位虚拟开关 |
| KEY | `0x8020_0010` | 读取 8 位虚拟按键 |
| SEG | `0x8020_0020` | 数码管数据寄存器 |
| LED | `0x8020_0040` | 32 位 LED 输出寄存器 |
| COUNTER | `0x8020_0050` | 跨时钟域性能计数器 |

BRAM 采用同步读取：MEM1 发起请求，数据在后续拍返回。MMIO 读取保持独立的组合数据路径。CPU 时钟驱动处理器和桥接逻辑，50 MHz 外设时钟单独提供给计数器。

## 2. CPU 双槽微架构

CPU 对外仍按 IF、ID、EX、MEM 和 WB 模块组织，但实际流水边界为：

`IF/ID -> ID/EX -> EX/MEM1 -> MEM1/MEM2 -> MEM2/WB`

图中的上下两条数据通路分别表示槽 0 和槽 1。槽 0 对应包内较老指令，槽 1 对应较年轻指令；提交时始终先处理槽 0，再处理槽 1。

为避免图面文字干扰流水关系，微架构图仅保留流水级、核心功能单元和反馈网络名称。预测表规模、发射限制、操作优先级、存储时序和异常处理等实现细节统一在以下各节说明。

### 2.1 取指与发射

IF 前端维护 PC、顺序下一 PC 和重定向选择逻辑，同时从两路 IROM 取得当前指令及其相邻指令。256 项直接映射提示表记录某一取指位置是否适合双发射，使复杂的包内合法性判断不进入 PC 关键反馈路径。

条件分支使用 64 项两位饱和计数 BHT。未训练的条件分支采用 BTFNT 策略，JAL 在 IF 阶段直接预测目标。发生误预测时，EX 槽 0 将正确目标反馈给 IF，并冲刷错误路径指令。

### 2.2 译码与寄存器堆

两个 ID 槽分别完成指令译码、立即数生成和寄存器索引提取。共享寄存器堆具有四个读口和两个写口，可同时为两个槽提供两个源操作数，并在同一拍接受两路顺序写回。

第二槽只有在包内不存在 RAW/WAW 相关且资源允许时有效。控制流、CSR、双访存和双 RV32M 等组合退化为单发射；因此槽 1 的控制流和 CSR 执行通路在 EX 阶段被静态关闭。

### 2.3 执行、停顿与重定向

两个 EX 槽均包含 RV32I ALU 和 RV32M 多周期运算单元。槽 0 额外包含 CSR 文件及分支、跳转、异常和陷阱返回的重定向逻辑。

任一 RV32M 单元忙时，前端和 ID/EX 保持，避免新指令覆盖尚未完成的多周期操作。误预测重定向优先冲刷 IF/ID 和 ID/EX，并通过 valid 信号屏蔽错误路径上的寄存器写、存储器写和 CSR 写副作用。

### 2.4 访存与 L0 缓存

CPU 对外只有一组数据总线，因此同一发射包最多包含一条访存指令。MEM1 负责选择有效槽并通过共享 LSU 发起地址、写数据和访问宽度请求；MEM2 对齐同步 BRAM 返回数据与流水元数据。

64 项直接映射 L0 cache 仅缓存 BRAM 的完整 32 位 load 结果。EX 阶段提前探测地址，命中时依赖指令可在下一拍从 MEM1 获得前递数据；未命中时，冒险单元等待同步 BRAM 数据进入后端。store 采用写穿策略，并失效相同字地址的缓存行。byte 和 half 的选择及符号扩展在后端完成。

### 2.5 冒险与前递

冒险单元同时检查两个消费者槽对 EX 和 MEM1 中两槽 load 的依赖，并产生 stall、flush 和 bubble 控制。L0 命中会使相应 load 被视为可提前获得，从而减少 load-use 停顿。

每个 EX 槽具有独立的前递选择器。候选数据来自 MEM1、MEM2 和 WB，阶段优先级依次为 MEM1、MEM2、WB；同一阶段内，槽 1 的结果优先于槽 0，以反映双槽顺序包中较新的写入。

### 2.6 写回与顺序提交

两个 WB 槽各自通过五路选择器形成最终写回值，候选来源包括普通 ALU 结果、load 数据、PC 相关结果、CSR 读值和其他已编码的非普通结果。load 的 byte/half 选择与有符号或无符号扩展在写回路径完成。

寄存器堆提供两个独立写端口，并带有 WB 到 ID 的同周期旁路。若两个槽在同一拍都有效，则槽 0 先于槽 1 按程序顺序提交；对 `x0` 的写入始终被屏蔽。图中的 `In-order Commit` 表示这种提交次序，并不表示额外增加了一个流水级。

## 3. 图中线型

| 线型 | 含义 |
|---|---|
| 蓝色实线 | 主数据流、取指和寄存器写回 |
| 橙色实线 | LSU、BRAM 和 L0 cache 访存路径 |
| 紫色实线 | MEM1、MEM2、WB 到 EX 的前递路径 |
| 红色虚线 | stall、flush、valid、busy 和重定向控制 |
