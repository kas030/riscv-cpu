# RV32 Zb 扩展现场加指令训练题库

本文用于比赛前练习“主办方临时给出一条指令，现场把它加入 CPU”的完整流程。
范围限定为 RV32 的 Zba、Zbb、Zbc、Zbs、Zbkb 和 Zbkx。这里给出的代码均为
实现思路或局部模板，**不表示这些指令已经接入本仓库 RTL**。

不同版本的 Bitmanip 规范可能存在名称或编码差异，尤其是 `brev8/rev.b`、
`xperm4/xperm.n`、`xperm8/xperm.b`。比赛时应以题面给出的语义和机器码为准，
不要仅凭助记符猜编码。

## 推荐使用顺序

这份文件是练习册，不建议直接从第一页硬啃到最后。更容易理解的顺序是：

1. 先读[主教程](zb_extension_competition_guide.md)，跟着 `sh1add` 完整做一遍。
2. 按下表由易到难做题，每次只实现一条指令。
3. 能独立完成后，使用[比赛速查表](zb_competition_cheatsheet.md)限时模拟。
4. 用 `vivado/tests/zb_training/tools/zb_tool.py` 独立计算机器码和期望结果。

| 阶段 | 建议题目 | 学习目标 |
|---|---|---|
| 入门 | 1、2、7、9 | 熟悉独热译码和简单组合结果 |
| 进阶 | 3、4、8、10 | 处理索引、立即数字段和归约逻辑 |
| 挑战 | 11、12、5、6 | 处理越界置换和较大的组合网络 |

每道题标题下的“难度、类别、前置”是学习提示，不是比赛难度保证。

## 1. 先熟悉现场工作流

当前基线中，`rtl/control/alu_ctrl.sv` 根据 `opcode` 和 `{funct7, funct3}`
产生 22 位独热 `ALUControl`，`rtl/datapath/alu.sv` 在 EX 级计算普通整数结果。
一条不访存、不跳转、单周期完成的 Zb 指令，通常按下列顺序接入：

1. 写出精确语义，确认两个输入分别来自 `rs1`、`rs2` 还是立即数字段。
2. 按题面匹配完整编码。若多条指令共享 `funct7/funct3`，必须进一步检查
   `instr[24:20]` 等字段，不能放宽成会误收保留编码的条件。
3. 扩展 `ALU_OP_WIDTH`，给新操作分配一个独热位；当前已有位为 `[21:0]`。
4. 在 ALU 控制译码中增加 `do_xxx`，在 ALU 中增加 `m_xxx` 和 `r_xxx`。
5. 将新结果接入现有独热结果汇总，不要改变其他操作的结果和分支 `isTrue`。
6. 检查新控制位没有被 RV32M 多周期启动条件误认为乘除法操作。
7. 先做定向向量，再测 `rd == rs1/rs2`、紧邻前递、load-use、写 `x0`。

工具链不认识助记符时，可直接发射原始指令。R 型编码公式为：

```text
word = (funct7 << 25) | (rs2 << 20) | (rs1 << 15)
     | (funct3 << 12) | (rd << 7) | opcode
```

OP-IMM 类指令可使用：

```text
word = (imm12 << 20) | (rs1 << 15) | (funct3 << 12)
     | (rd << 7) | opcode
```

推荐在汇编测试中用宏隐藏寄存器编号和编码拼接；若使用 `.word`，务必查看生成的
`.dump`，确认机器码与题面一致。

## 3. Zba：移位后加法

### 题 1：实现 `sh1add`

> 难度：入门｜类别：常量移位加法｜前置：主教程完整示例

**题面**

实现 RV32 `sh1add rd, rs1, rs2`：

```text
rd = (rs1 << 1) + rs2    // 只保留低 32 位
```

它常用于计算以 2 字节为元素宽度的数组地址。

**提示**

- 这是 R 型双源指令，`rs2` 不是移位量，而是加数。
- 左移溢出自然截断，不需要饱和处理。
- 可以先写成移位与加法的组合表达式；不要为了“复用”现有 ALU 而让一条指令走
  两个周期。

**参考实现思路**

在 ALU 内增加独立结果：

```systemverilog
logic [31:0] r_sh1add;
assign r_sh1add = (A << 1) + B;
```

译码严格匹配题面给出的 `opcode/funct7/funct3`，再将 `r_sh1add` 通过新的
独热控制位并入 `Result`。

**测试向量**

| `rs1` | `rs2` | 期望 `rd` | 检查点 |
|---:|---:|---:|---|
| `0x00000000` | `0x00000000` | `0x00000000` | 全零 |
| `0x00000003` | `0x00000005` | `0x0000000B` | 普通值 |
| `0x40000001` | `0x00000003` | `0x80000005` | 最高位附近 |
| `0x80000000` | `0x00000001` | `0x00000001` | 左移溢出截断 |

## 4. Zbb：基础位操作

### 题 3：实现 `ror`

> 难度：进阶｜类别：变量旋转｜前置：题 1

**题面**

实现循环右移：

```text
shamt = rs2[4:0]
rd = ror32(rs1, shamt)
```

右侧移出的位应从左侧重新进入。

**提示**

- RV32 的寄存器移位量只取低 5 位。
- 直接写 `(A >> n) | (A << (32-n))` 时，`n=0` 会产生移位 32 的边界问题。
- 拼接后移位可以自然处理 `n=0`。

**参考实现思路**

```systemverilog
logic [63:0] ror_double;
assign ror_double = {A, A};
assign r_ror      = ror_double >> B[4:0];
```

这里把 64 位结果赋给 32 位 `r_ror`，保留低 32 位。也可以对 `shamt==0` 单独
分支，再使用两个方向的移位。

**测试向量**

| `rs1` | `rs2` | 期望 `rd` | 检查点 |
|---:|---:|---:|---|
| `0x80000001` | `0` | `0x80000001` | 零移位 |
| `0x80000001` | `1` | `0xC0000000` | 首尾回卷 |
| `0x12345678` | `8` | `0x78123456` | 按字节旋转 |
| `0x00000001` | `33` | `0x80000000` | 只取低 5 位 |

### 题 4：实现 `cpop`

> 难度：进阶｜类别：位计数与精确立即数译码｜前置：题 1

**题面**

实现人口计数 `cpop rd, rs1`，结果为 `rs1` 中 1 的个数，范围为 0 到 32。

**提示**

- 这是单源指令，但编码位置可能与其他 Zbb 单目指令共享
  `opcode/funct7/funct3`。
- `instr[24:20]` 在这类编码中可能是功能选择字段，不应当被冒险单元当成真实
  `rs2`。至少要确认当前译码器和源寄存器使用标志的处理方式。
- 不要用不可综合的运行时软件循环。

**参考实现思路**

用固定上界的组合循环，综合器会展开成加法树或加法链：

```systemverilog
integer i;
always_comb begin
    r_cpop = 32'b0;
    for (i = 0; i < 32; i = i + 1)
        r_cpop = r_cpop + A[i];
end
```

现场优先保证功能正确；若时序压力明显，再改为分组计数和树形求和。

**测试向量**

| `rs1` | 期望 `rd` |
|---:|---:|
| `0x00000000` | `0` |
| `0xFFFFFFFF` | `32` |
| `0x80000000` | `1` |
| `0xF0F0000F` | `12` |
| `0xAAAAAAAA` | `16` |

## 5. Zbc：无进位乘法

### 题 5：实现 `clmul`

> 难度：挑战｜类别：循环生成组合网络｜前置：题 4

**题面**

实现低 32 位无进位乘法。它把每一位看作 GF(2) 多项式系数，部分积用异或而非
普通加法累加：

```text
product = XOR over every i where rs2[i]==1 of (uint64(rs1) << i)
rd = product[31:0]
```

**提示**

- “无进位”意味着 `1 + 1 = 0`，不能复用普通乘法结果。
- 中间量建议使用 64 位，否则高位部分积会在循环中提前丢失。
- 本题虽属于 Zbc，也不应自动接入现有 RV32M 多周期乘除控制。

**参考实现思路**

```systemverilog
integer i;
always_comb begin
    cl_product = 64'b0;
    for (i = 0; i < 32; i = i + 1)
        if (B[i])
            cl_product = cl_product ^ ({32'b0, A} << i);
end
assign r_clmul = cl_product[31:0];
```

**测试向量**

| `rs1` | `rs2` | 期望 `rd` |
|---:|---:|---:|
| `0x00000000` | `0x12345678` | `0x00000000` |
| `0x0000000B` | `0x00000006` | `0x0000003A` |
| `0x80000000` | `0x00000002` | `0x00000000` |
| `0xFFFFFFFF` | `0x00000001` | `0xFFFFFFFF` |

### 题 6：在同一乘积上实现 `clmulh`

> 难度：挑战｜类别：共享中间结果与结果切片｜前置：题 5

**题面**

实现 `clmulh`，返回 64 位无进位乘积的高 32 位：

```text
rd = cl_product[63:32]
```

**提示**

本题最容易出现两类错误：一是仍取低 32 位，二是用 32 位中间量导致高半部分永远
为零。若题目给的是 `clmulr`，其结果窗口不同，不能把两者混为一谈。

**参考实现思路**

与上一题共享 `cl_product` 的生成网络，但给 `clmulh` 分配独立译码位，并选择
`cl_product[63:32]`。比赛只要求一条指令时，保留最直白的实现即可。

**测试向量**

| `rs1` | `rs2` | 期望 `rd` | 检查点 |
|---:|---:|---:|---|
| `0x80000000` | `0x00000002` | `0x00000001` | 乘积第 32 位 |
| `0x80000000` | `0x80000000` | `0x40000000` | 乘积第 62 位 |
| `0xFFFFFFFF` | `0x00000001` | `0x00000000` | 高半为零 |
| `0x00000000` | `0xFFFFFFFF` | `0x00000000` | 零输入 |

## 6. Zbs：单比特操作

### 题 7：实现 `bset`

> 难度：入门｜类别：单比特掩码｜前置：题 1

**题面**

将 `rs1` 中由 `rs2` 指定的一位置 1：

```text
index = rs2[4:0]
rd = rs1 | (32'b1 << index)
```

**提示**

索引必须只取低 5 位。掩码常量应为 32 位，避免无尺寸常量带来的宽度或符号问题。

**参考实现思路**

```systemverilog
assign r_bset = A | (32'b1 << B[4:0]);
```

紧邻依赖是本题的重点：先生成 `rs1`，下一条立即 `bset`；再让后一条立即消费
`bset` 的 `rd`，用于确认原有前递通路无需特殊修改。

|---:|---:|---:|
| `0x00000000` | `0` | `0x00000001` |
| `0x00000000` | `31` | `0x80000000` |
| `0x00000010` | `4` | `0x00000010` |

### 题 8：实现 `bext`，并比较 `bexti`

> 难度：进阶｜类别：寄存器/立即数共用数据通路｜前置：题 7

**题面**

实现单比特提取：

```text
index = rs2[4:0]
rd = (rs1 >> index) & 1
```

随后说明若题目改成 `bexti`，数据来源和译码需要如何变化。

**提示**

- `bext` 是寄存器版本，索引来自真实 `rs2`。
- `bexti` 是立即数版本，索引来自指令中的立即数字段，不应读取第二个寄存器。
- 结果只能是 0 或 1，其余 31 位必须清零。

**参考实现思路**

```systemverilog
assign r_bext = {31'b0, A[B[4:0]]};
```

立即数版本若沿用 ALU 的 B 输入，需要确认 ID/EX 已选择正确的立即数；如果主控制
只按普通 OP-IMM 分类，通常无需新增写回路径，但必须核对源寄存器使用标志，避免
假 `rs2` 冒险。

|---:|---:|---:|
| `0x80000001` | `0` | `1` |
| `0x80000001` | `1` | `0` |

### 题 10：实现 `brev8`

> 难度：进阶｜类别：固定位置换与精确立即数译码｜前置：题 9

**题面**

分别反转每个字节内部的位序，字节在 32 位字中的位置保持不变。例如：

```text
0x01_23_45_67 -> 0x80_C4_A2_E6
```

**提示**

- 不是把四个字节倒序；那是另一类字节置换。
- 适合用双层固定循环表达：外层选择字节，内层反转该字节的 8 位。
- 固定置换综合后主要是连线，代码写得清晰比手工列 32 个赋值更重要。

**参考实现思路**

```systemverilog
integer byte_i, bit_i;
always_comb begin
    r_brev8 = 32'b0;
    for (byte_i = 0; byte_i < 4; byte_i = byte_i + 1)
        for (bit_i = 0; bit_i < 8; bit_i = bit_i + 1)
            r_brev8[byte_i*8 + bit_i] = A[byte_i*8 + (7-bit_i)];
end
```

**测试向量**

| `rs1` | 期望 `rd` |
|---:|---:|
| `0x01234567` | `0x80C4A2E6` |
| `0x00000001` | `0x00000080` |
| `0x80000000` | `0x01000000` |
| `0xFFFFFFFF` | `0xFFFFFFFF` |

## 8. Zbkx：交叉置换

### 题 11：实现 `xperm8`

> 难度：挑战｜类别：字节查表置换｜前置：题 10

**题面**

把 `rs1` 看成 4 个 8 位元素。`rs2` 的每个目标字节给出一个无符号索引：索引
小于 4 时，从 `rs1` 选择对应字节；否则该目标字节写零。

```text
for i in 0..3:
    index = rs2[i*8 +: 8]
    rd[i*8 +: 8] = index < 4 ? rs1[index*8 +: 8] : 0
```

**提示**

- 低字节是元素 0。
- 必须比较完整 8 位索引是否小于 4，不能只取低 2 位；否则越界索引会错误回卷。
- SystemVerilog 可变 part-select 的基址可以由索引计算，宽度必须为常量 8。

**参考实现思路**

```systemverilog
integer i;
logic [7:0] index;
always_comb begin
    r_xperm8 = 32'b0;
    for (i = 0; i < 4; i = i + 1) begin
        index = B[i*8 +: 8];
        if (index < 4)
            r_xperm8[i*8 +: 8] = A[index*8 +: 8];
    end
end
```

实际编码时，循环内共用一个临时 `index` 可能不利于部分工具分析；可以改成直接
引用 `B[i*8 +: 8]`，或为每个目标元素展开独立组合逻辑。

**测试向量**

| `rs1` | `rs2` | 期望 `rd` | 检查点 |
|---:|---:|---:|---|
| `0x44332211` | `0x00010203` | `0x11223344` | 逆序选择 |
| `0x44332211` | `0x03020100` | `0x44332211` | 恒等选择 |
| `0x44332211` | `0x04040404` | `0x00000000` | 全部越界 |
| `0x44332211` | `0x00040502` | `0x11000033` | 混合有效/越界 |

### 题 12：实现 `xperm4`

> 难度：挑战｜类别：半字节查表置换｜前置：题 11

**题面**

把 `rs1` 看成 8 个 4 位元素。`rs2` 的每个目标 nibble 是索引；索引小于 8 时
选择对应 nibble，否则写零。

**提示**

本题不能简单把 `xperm8` 中的常数 8 改成 4：循环次数、索引字段宽度、有效索引
范围和动态选择宽度都要一起修改。

**参考实现思路**

```systemverilog
integer i;
logic [3:0] index;
always_comb begin
    r_xperm4 = 32'b0;
    for (i = 0; i < 8; i = i + 1) begin
        index = B[i*4 +: 4];
        if (index < 8)
            r_xperm4[i*4 +: 4] = A[index*4 +: 4];
    end
end
```

**测试向量**

|---:|---:|---:|---|
| `0x76543210` | `0x01234567` | `0x01234567` | 反向选择 |
| `0x76543210` | `0x76543210` | `0x76543210` | 恒等选择 |

## 9. 每道题完成后的加测清单

基础向量通过后，至少补齐以下流水相关场景：

1. `rd == rs1`，确认写回不会破坏本条指令读取的旧值。
2. `rd == rs2`（双源指令），确认第二源也能正确读取旧值。
3. 上一条 ALU 指令生成本条的 `rs1` 或 `rs2`，验证 EX/MEM 前递。
4. 再隔一条指令消费结果，验证 MEM/WB 前递。
5. load 后立即把加载值作为输入，验证 load-use 停顿后结果正确。
6. 将结果写入 `x0`，随后确认 `x0` 仍为零。
7. 在结果刚产生后立即用 `bne` 检查，避免测试被额外 `nop` 掩盖前递错误。
8. 检查无关 RV32I、RV32M 指令仍通过，尤其是与新指令共享 `funct3` 的操作。

若仿真没有结束，先区分“计算错误”和“镜像未更新”：检查 `.dump` 中是否存在目标
机器码，确认 Vivado IROM 实际加载的是刚生成的 `.coe/.mif`，并确认程序最终确实
向 `0x80200040` 写入完成码。

## 10. 现场讲解建议

讲解一条新指令时，可以固定使用四句话：

1. “先把语义写成 32 位数学表达式，边界是这些。”
2. “再拆机器码，确认哪些字段真的是源操作数。”
3. “这条指令走现有普通 ALU 写回，只新增严格译码和一个组合结果。”
4. “最后用普通值、边界值和流水依赖三组测试证明它正确。”

这样可以把注意力放在最容易失分的三件事上：编码匹配过宽、位宽/索引边界错误，
以及功能值正确但冒险与前递场景失败。
